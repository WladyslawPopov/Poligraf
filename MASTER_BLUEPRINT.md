# 📑 MASTER BLUEPRINT: LieDetector (KMP AI Ecosystem)

## 1. СТРАТЕГИЧЕСКОЕ ВИДЕНИЕ
*   **Продукт:** Глобальная платформа верификации речи на основе ИИ.
*   **Бизнес-цель (Data Flywheel):** Использовать Google Gemini как временный «движок» для сбора и разметки уникальной базы аудиоданных.
*   **Конечная цель:** Обучение собственной проприетарной нейросети на собранных данных, полный отказ от внешних API, снижение себестоимости и выход в B2B сектор (API для финтеха, банков и мессенджеров).

## 2. ТЕХНОЛОГИЧЕСКИЙ СТЕК
*   **Клиент (Native UI):**
    *   **Android:** Kotlin + Jetpack Compose.
    *   **iOS:** Swift + SwiftUI.
    *   *Причина:* Прямой доступ к аудио-буферам, низкая задержка, нативные Haptics и плавная анимация звуковой волны.
*   **Shared Logic (KMP):** Модуль `:app:sharedLogic`. Общий сетевой слой (Ktor Client), модели данных и бизнес-правила для мобильных платформ.
*   **Backend:** Ktor (Server KMP). Разворачивается в **Docker** на **Google Cloud Run**.
*   **База данных:** **PostgreSQL** (через Exposed ORM). Выбрана для обеспечения гибкости, аналитики и суверенитета данных.
*   **AI Engine:** Google Gemini 1.5 (через Vertex AI на стороне сервера).
*   **Infrastructure:**
    *   **Firebase Auth:** Авторизация пользователей.
    *   **Google Cloud Storage:** Хранение аудиофайлов (доступ через Firebase SDK на клиенте).

## 3. АРХИТЕКТУРА МОДУЛЕЙ
1.  **`:core` (KMP):** Общие `Serializable` модели данных (DTO). Используются Сервером, Android и iOS приложениями.
2.  **`:app:sharedLogic` (KMP):** Общая бизнес-логика для мобильных платформ (API-клиент, репозитории, обработка ошибок).
3.  **`:server` (Ktor/JVM):** Серверная логика, работа с БД, интеграция с Gemini API.
4.  **`:app:androidApp` (Native):** Android-специфичный код: Compose UI + нативный захват звука.
5.  **`:app:iosApp` (Native):** iOS-специфичный код: SwiftUI UI + нативный захват звука (AVFoundation).

## 4. ЖИЗНЕННЫЙ ЦИКЛ ЗАПРОСА (DATA FLOW)
1.  **Запись:** Нативное приложение записывает аудио -> Загрузка в Firebase Storage -> Получение ID файла.
2.  **Анализ:** Приложение отправляет запрос `analyze(file_id)` на Ktor-сервер через `sharedLogic`.
3.  **Обработка:**
    *   Сервер проверяет токен пользователя.
    *   Сервер запрашивает анализ у Gemini.
    *   Результат сохраняется в **PostgreSQL** со статусом `pending_feedback`.
4.  **Вердикт:** Сервер возвращает результат (Ложь/Правда + метрики стресса).
5.  **Обратная связь (Flywheel):** Пользователь подтверждает точность -> Сервер обновляет запись в БД. Данные размечаются для будущего обучения.

## 5. ЭКОНОМИЧЕСКИЙ ПЛАН
*   **Этап 1 (MVP Development):** Полностью локальная разработка (Server + Postgres в Docker). **Цена: 0$.**
*   **Этап 2 (Alpha Launch):** Cloud Run (Server) + Дешевый VPS/Serverless DB (Postgres). **Цена: ~$5-10/мес.**
*   **Этап 3 (Scaling):** Переезд в Google Cloud SQL при достижении критической массы данных.
