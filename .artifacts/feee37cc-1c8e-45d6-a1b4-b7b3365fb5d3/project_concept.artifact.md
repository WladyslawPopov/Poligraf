# Организация фундамента проекта: «Цифровой Детектив»

Этот документ фиксирует базовую концепцию и философию приложения Lie Detector. Все технические решения должны опираться на эти принципы.

### 1. Философия вовлечения и Авторизация (Onboarding & Auth)
*   **Мгновенный старт (Root)**: Как только пользователь попадает в приложение, система автоматически создает анонимную запись через **Firebase Anonymous Auth**.
*   **Сбор метаданных**: Сразу после входа собираются все доступные технические метаданные (язык, локаль, модель телефона, часовой пояс). Это формирует «Базовый контекст Детектива» еще до первого клика.
*   **Линейный Onboarding (Рука в руку)**: Для анонимного пользователя интерфейс максимально упрощен и линеен. Мы ведем его «за руку» по строгому пути: *Нажать кнопку -> Записать голос -> Ввести контекст -> Получить результат*. Все остальные функции (галерея, детальные профили, настройки) визуально заблокированы или скрыты.
*   **Эффект FOMO и "Крючок"**: После завершения первого анализа пользователь видит «инсайт», который показывает, что текущий результат — это лишь 10% от возможной глубины. Мы демонстрируем заблокированные возможности (добавление скриншотов, анализ психотипа, история связей) как способ значительно повысить качество «расследования».
*   **Воронка конверсии**:
    1. Анонимный режим: Линейный путь «только запись», жесткие лимиты на количество попыток.
    2. Осознание ценности: Пользователь сам хочет «дополнить дело», увидев скрытый потенциал.
    3. Регистрация: Единственный способ разблокировать «полный арсенал детектива» и сохранить накопленные материалы.
    4. Удержание: После авторизации пользователь получает доступ к архиву и инструментам, превращая разовое действие в привычку.

### 2. Монетизация и Ограничения (Теоретическая база)
*   **Модель**: Freemium / Subscription.
*   **Free (Базовый)**: Ограниченная длина аудиозаписи, лимит на количество анализов в день.
*   **Pro (Продвинутый)**: Неограниченная длина записей, приоритетная обработка, расширенные отчеты ИИ, отсутствие лимитов.
*   **Реклама (Перспектива)**: Возможность получить дополнительный анализ за просмотр Reward-видео (будет реализовано после MVP).

### 2. Структура экрана «Расследование» (Investigation)

**Верхний уровень (Контекст Субъекта)**:
*   **Тулбар**: Отображает имя (дефолт: `Undefined-N`) и иконку (случайный emoji).
*   **Функциональность**: Тулбар кликабелен. Это точка входа для детального редактирования профиля субъекта (имя, фото, дополнительные факты).

**Центральный уровень (Материалы дела)**:
*   **Лента**: Хронологический список добавленных «улик» (аудиозаписи, скриншоты диалогов, фотографии, текстовые заметки).
*   **Интерактивность**: Каждый материал — это карточка с возможностью редактирования (например, обрезка аудио или правка текста).
*   **Разделение**: Визуальное разграничение между первичными материалами дела и результатами проведенных анализов. Результаты анализов также сохраняются в ленте.

**Нижний уровень (Панель инструментов)**:
*   **Кнопки быстрого добавления**: Три основных инструмента:
    1. `[Микрофон]` — захват голоса.
    2. `[Галерея]` — импорт визуальных доказательств.
    3. `[Текст/Контекст]` — добавление описания ситуации и мыслей пользователя.
*   **Динамическая кнопка «Анализ»**: Появляется только тогда, когда в ленте есть хотя бы один материал.

### 3. Механика Анализа
*   **Пре-анализ**: Короткий запрос пользователю «Опишите ситуацию» непосредственно перед запуском обработки.
*   **Результат**: Вердикт системы + «Insights» — подсказки, какие именно данные можно добавить, чтобы сделать следующий анализ точнее.
*   **Итеративность**: Возможность использовать имеющиеся материалы для повторных анализов с учетом новых вводных.

### 4. Слои контекста для ИИ (Промт-инжиниринг)
Для формирования качественного запроса к ИИ используются данные из четырех источников:
1.  **Детектив (User)**: Метаданные владельца приложения + его настройки.
2.  **Субъект (Subject)**: Данные из карточки подозреваемого.
3.  **Материалы (Case Materials)**: Совокупность выбранных для анализа аудио, фото и текстов.
4.  **Ситуация (Context)**: Краткое описание, введенное пользователем прямо перед анализом.
